# ADR-001: Тема диплома — прогноз энергопотребления предприятия: временные признаки и отбор факторов для CatBoost

**Статус:** Предложено (ждёт согласования с руководителем)
**Дата:** 29.09.2026
**Кто решает:** Дио (автор), А. С. Сысоев (руководитель)
**Журнал решений по реализации:** `docs/DECISIONS_FORECAST.md`

---

## Контекст

- Текущий стенд (`diploma_fs`) сравнивает 11 методов выбора формы признаков (log, sqrt, …) на 12 датасетах. Итог «всё примерно одинаково»: прирост качества мал (Ridge — нет, MLP — +0.01..0.02 R² только на синтетике), новизна слабая (метод shape_fit повторяет ACE/SAFE).
- Цель автора — сдать диплом с понятной историей, где **метрики модели реально растут**.
- Демонстрация на модельном заводе (29.09): добавление прошлых значений подняло R² с 0.52 до 0.95 (ошибка 21.5 → 6.5 кВт·ч); отбор 6 из 30 датчиков поднял R² с 0.846 до 0.881 и нашёл ровно правильные датчики.
- Ограничения: слабый ноутбук (Intel N95, без GPU, Windows); ветку `main` и папку `app/` не трогаем; руководитель — автор статьи об отборе факторов для CatBoost (SUMMA 2023).

## Решение

Сузить работу до одной темы из двух связанных частей:

1. **Временные признаки** (главный рост качества): лаги, скользящие средние, «то же время вчера/неделю назад», календарь.
2. **Отбор факторов для CatBoost** (компактность и устойчивость): после шага 1 признаков 30–50; сравниваем способы отбора, включая метод Сысоева (оригинал и исправленный).

**Главный вопрос работы:** насколько временные признаки повышают точность прогноза энергопотребления и сколько из них можно отбросить без потери качества?

## Рассмотренные варианты

### Вариант A: временные признаки + отбор для CatBoost (выбран)
| Критерий | Оценка |
|---|---|
| Сложность | Средняя — половина кода уже есть |
| Рост метрик | Высокий (ожидаем ошибку ниже в 2–3 раза) |
| Нагрузка на ноутбук | Приемлемая (≤10 тыс. строк, CatBoost на CPU) |
| Связь с руководителем | Прямая (его статья — глава 2) |

**Плюсы:** понятная история для защиты; заметный прирост качества; переиспользуются разбиение по времени, статистика, отчёт, методы Сысоева.
**Минусы:** прогноз временных рядов — известная область, новизна в сочетании и в честном сравнении, а не в методе.

### Вариант B: только временные признаки
**Плюсы:** проще всего. **Минусы:** нет связи со статьёй руководителя, слабее научная часть.

### Вариант C: продолжать выбор форм признаков (текущая тема)
**Плюсы:** всё готово. **Минусы:** прироста качества почти нет, новизна слабая — сам автор считает результат слабым.

### Вариант D: подготовка признаков для TabPFN/TabICL
**Плюсы:** модная тема 2026. **Минусы:** на неё уже вышли две статьи (TabPrep, «Do TFMs still need FE?»); тяжёлые модели на N95; тема оказалась непонятной автору.

## Анализ компромиссов

A даёт лучший баланс «рост метрик / объём работы / защищаемость». B проще, но беднее; C и D проигрывают по пользе и понятности. Цена A — нужно аккуратно избежать утечки будущего в признаки (см. «Риски»).

## Архитектура стенда (что меняется в коде)

Конвейер остаётся тем же (7 шагов), меняются шаги 3–5:

| Шаг | Было | Станет |
|---|---|---|
| 1. Данные | 12 датасетов | 2–3 временных: **steel**, **tetouan**, (seoul_bike — по часам) |
| 2. Разбиение | forward-chaining, зазор 1% | то же; зазор ≥ горизонта прогноза |
| 3. Признаки | формы (GroupFE) | **LagFE**: лаги, скользящие окна, календарь; всё считается только из прошлого |
| 4. Отбор | 11 методов форм | важность CatBoost, перестановочная важность, SHAP, RFE, Boruta, **Сысоев (оригинал и исправленный)** |
| 5. Модели | Ridge / MLP / HGB | **наивный прогноз** / **GLM** / **XGBoost** / **CatBoost** (+ лёгкая настройка Optuna) — уточнено 29.09, см. журнал решений |
| 6. Метрики | R², MAE, RMSE | + MAE в кВт·ч, MAPE, время обучения, число признаков |
| 7. Статистика | Wilcoxon + Holm, Фридман + Nemenyi | без изменений |

**Два режима задачи** (важно для честности):
- **Прогноз** — известны только прошлые значения всех величин (в т.ч. датчиков). Основной режим.
- **Виртуальный датчик** — текущие показания датчиков известны. Второстепенный режим для сравнения.

## Эксперименты (критерии фиксируются ДО прогона)

| № | Вопрос | Критерий успеха |
|---|---|---|
| E1 | Дают ли временные признаки рост? | MAE CatBoost с лагами ниже, чем без лагов, на всех основных датасетах; значимо по Wilcoxon (p_holm < 0.05) |
| E2 | Какие группы признаков важнее? | Абляция: календарь / короткие лаги / суточные / скользящие окна / датчики — вклад каждой |
| E3 | Сколько признаков можно отбросить? | Лучший отбор оставляет ≤ 50% признаков при ΔMAE ≤ 2% от полного набора |
| E4 | Метод Сысоева | Оригинал vs исправленный vs остальные: место в рейтинге Фридмана, устойчивость отбора ≥ 0.6 |

Окончательная формулировка — `docs/FORECAST.md`, «Критерий C».

## Последствия

- **Проще:** защита (одна история, одна главная таблица), понятный рост метрик, руководитель видит развитие своей статьи.
- **Сложнее:** контроль утечек в лагах; CatBoost + Optuna дольше считать на ноутбуке.
- **Пересмотреть позже:** брать ли третий датасет; нужна ли глава с формами признаков или хватит приложения.

## Риски

| Риск | Что делаем |
|---|---|
| Утечка будущего в лаги | лаги строятся сдвигом ≥ горизонта; тест: признак в момент t зависит только от данных до t − h |
| Долгий счёт на N95 | подвыборка 10 тыс. строк, Optuna ≤ 30 попыток, CatBoost 500 деревьев, прогон ночью через дашборд |
