# Формат отчёта по экспериментам (согласован 29.09.2026)

Отчёт должен читаться без знания кода. Образец (числа условные): `python scripts/make_report_sample.py` → `docs/REPORT_SAMPLE.pdf`.
Реальный отчёт строит `scripts/report_forecast.py` в двух видах: `docs/FORECAST_REPORT.md` и PDF/HTML.

## Правила читаемости

1. **Ни одного кода без расшифровки.** Столбцы, признаки, модели, методы — по-русски; технический код,
   если нужен, один раз в скобках: «потребление 1 ч назад (`target.short__lag4`)».
2. **Значения категорий расшифрованы:** `Light_Load` → «лёгкая нагрузка», `Weekday` → «рабочий день».
3. **У каждого числа есть единица:** кВт·ч, %, с. Округление: ошибки — 2 знака, R² — 3 знака, доли — целые %.
4. **Статистика словами:** «значимо лучше (p = 0.004)» / «разница не доказана (p = 0.31)»; голых p-value нет.
5. **Техника — простыми словами:** «9 фолдов» → «9 проверок на разных отрезках года»; «warmup» → «первая неделя
   ряда нужна для расчёта недельного лага и в оценку не входит».
6. Каждая таблица и график подписаны: что показано и как читать («меньше — лучше»).

## Структура

| № | Раздел | Что внутри |
|---|---|---|
| 0 | **Итог** | 3–4 строки: лучшая модель, ошибка в кВт·ч, во сколько раз лучше без прошлого и наивного прогноза, сколько признаков оставил отбор |
| 1 | **Задача** | что прогнозируем, единицы, горизонт, что известно в момент прогноза, как проверяем (прошлое → будущее) |
| 2 | **Вход: исходные данные** | паспорт (источник, период, шаг, строк, пропуски); **первые 5 строк** таблицы с русскими заголовками и расшифрованными значениями; **таблица столбцов**: имя в файле → смысл → единицы → роль (цель / известно заранее / только прошлое / удалено и почему) |
| 3 | **Признаки: что видит модель** | одна строка «глазами модели» (признак по-русски, значение, смысл); таблица групп признаков (календарь, короткие лаги, суточные, окна, датчики) с числом признаков |
| 4 | **Модели** | таблица: название → что делает простыми словами → основные настройки |
| 5 | **Выход: пример прогноза** | 8–10 моментов теста: время, факт, прогноз каждой модели, ошибка; график «факт и прогнозы» за неделю |
| 6 | **Результат и сравнение** | главная таблица «модель × набор признаков» (MAE кВт·ч, MAPE %, R², время, число признаков) + вывод словами; E2 — диаграмма вклада групп; E3/E4 — таблица методов отбора (сколько оставил, какие признаки по-русски, потеря точности, устойчивость); сравнение с опубликованными работами (их постановка, их число, наше в той же постановке, сопоставимо ли) |
| 7 | **Выводы и словарик** | E1–E4: выполнен / не выполнен и почему; словарик метрик и терминов |

## Модели для сравнения

| Модель | Код в результатах | Кратко |
|---|---|---|
| Наивный «как час назад» | `naive_last` | последнее известное значение — нижняя планка |
| Наивный «как вчера» | `naive_day` | значение сутки назад в то же время |
| GLM (линейная регрессия) | `glm` | взвешенная сумма признаков; вариант с регуляризацией — `ridge` |
| XGBoost | `xgboost` | градиентный бустинг деревьев |
| CatBoost | `catboost` | градиентный бустинг, основная модель работы |

## Где хранятся расшифровки

- Столбцы датасета и значения категорий — в `fsx/registry.py`, поле `labels` у каждого датасета
  (`{"Usage_kWh": ("Потребление", "кВт·ч", "цель"), ...}`, `values: {"Load_Type": {"Light_Load": "лёгкая"}}`).
- Признаки — функция `describe(col)` в `fsx/lags.py` («target.daily__lag96» → «потребление сутки назад»).
- Модели, методы отбора, метрики — словари в `scripts/report_forecast.py`.
