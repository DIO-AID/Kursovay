# Ветка research/forecast: прогноз энергопотребления (ADR-001)

Тема: временные признаки (лаги, скользящие окна, календарь) + отбор признаков для CatBoost.
Главный вопрос: насколько временные признаки повышают точность прогноза энергопотребления
и сколько из них можно отбросить без потери качества?

## Как запустить

```bash
python scripts/run_forecast.py --dataset synth_factory --quick   # проверка, ~5 мин
python scripts/run_forecast.py --dataset steel tetouan           # основной прогон (надолго, лучше на ночь)
python scripts/run_forecast.py --dataset steel --mode virtual    # режим «виртуальный датчик»
python scripts/report_forecast.py                                # -> docs/FORECAST_REPORT.md
python -m pytest tests -q                                        # тест на утечку будущего и др.
```

Нужен CatBoost (`requirements-extra.txt`); без него скрипт честно подменяет его
HistGradientBoosting и пишет об этом в отчёте. Код: `fsx/lags.py` (LagFE), `fsx/models.py`,
`fsx/selectors/catboost_sel.py`, `fsx/forecast.py`.

Результаты: `results/forecast/<режим>/raw/<датасет>/<метод>.json`, отчёт — `docs/FORECAST_REPORT.md`
(создаётся скриптом, в git не кладём, пока прогон сделан без CatBoost).

## Что где в коде

| Файл | Что делает |
|---|---|
| `fsx/lags.py` | LagFE: лаги цели (короткие, суточные, недельный), скользящие среднее/СКО, календарь, прошлые показания датчиков; `check_no_leak` — тест на утечку будущего |
| `fsx/models.py` | наивные прогнозы, Ridge, CatBoost (без пакета — HistGradientBoosting с пометкой `hgb_fallback`), настройка Optuna |
| `fsx/selectors/catboost_sel.py` | отбор по важности CatBoost, перестановкам, SHAP с общим правилом «сколько оставить» |
| `fsx/forecast.py` | конвейер: признаки → разбиение «прошлое → будущее» → наборы E1/E2 → отбор E3/E4 → JSON |
| `scripts/run_forecast.py`, `scripts/report_forecast.py` | запуск и отчёт |
| `tests/test_lags.py`, `tests/test_selectors_forecast.py` | утечка, сдвиги по времени, разбиение, методы отбора |
| `fsx/data.py` → `synth_factory` | модельный завод: 30 датчиков, 6 влияют на потребление с запаздыванием ~1.5 ч |

Сысоев: методы `sysoev_paper` и `sysoev_fixed` работают на новых признаках без изменений; группа
признака — всё до `__` (например, `target.short` — все короткие лаги цели), поэтому исправленный
метод берёт из каждой группы по одному признаку.

## Критерий C (фиксируется до прогона)

Зафиксирован 2026-09-29, **до** прогона на реальных данных. Датасеты: `steel`, `tetouan`
(основные), `seoul_bike` — по возможности; `synth_factory` — только проверка кода.
Режим `forecast` (прошлое всех величин, горизонт 1 ч) — основной; `virtual` — для сравнения.
Модель для вердиктов — CatBoost (500 деревьев); если в отчёте стоит `hgb_fallback`,
CatBoost не был установлен, и вердикты не засчитываются. Сравнение по фолдам (9 блоков
«прошлое → будущее»), Уилкоксон, Холм внутри эксперимента, α = 0.05. Метрика — MAE.

| № | Вопрос | Критерий успеха |
|---|---|---|
| E1 | Дают ли временные признаки рост? | MAE CatBoost на `fs_all` ниже, чем на `fs_no_lags`, на **всех** основных датасетах, p_holm < 0.05. Отдельно сообщаем, обгоняет ли модель наивный прогноз (без этого рост — не заслуга модели) |
| E2 | Какие семейства важнее? | Абляция «все минус одно»: calendar / short / daily / rolling / exog. Семейство **важное**, если без него MAE растёт значимо (p_holm < 0.05); критерия «успеха» нет — это описание |
| E3 | Сколько можно отбросить? | Метод проходит, если на всех основных датасетах оставляет ≤ 50% признаков при росте MAE ≤ 2% от `fs_all` и ни разу не даёт пустой отбор |
| E4 | Метод Сысоева | Место `sysoev_paper` и `sysoev_fixed` в рейтинге Фридмана (блоки «датасет × фолд», CD Неменьи) и устойчивость (средний Жаккар) ≥ 0.6 |

Правила честности: признаки строки t — только из данных до t − h (тест `check_no_leak` перед
каждым прогоном и `tests/test_lags.py`); первые строки без недельного лага выбрасываются для
всех наборов одинаково; настройка Optuna — только на train первого фолда, затем параметры
замораживаются; пустой отбор оценивается прогнозом средним train, а не выбрасывается.
