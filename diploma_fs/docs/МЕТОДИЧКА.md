# Методичка: что мы делаем и как это читать

Простым языком, без формул. Цифры — из цикла 1 (синтетика + diabetes), подробности в
[REPORT.md](REPORT.md), решения в [DECISIONS.md](DECISIONS.md).

## 1. О чём работа

У каждого фактора (например, «площадь дома») можно взять разные **модификации**:
как есть (raw), логарифм (log), корень (sqrt), квадрат (sq), обратное (1/x, inv).
Для линейной модели выбор важен: если зависимость логарифмическая, а мы подали x «как есть»,
модель ошибается. Для бустинга (деревьев) почти всё равно: дерево делит данные по порогам,
а порог «x > 3» и «log x > log 3» режут одно и то же.

Вопрос работы: **как автоматически выбрать для каждого фактора одну правильную модификацию**
и чем это полезно интерпретируемым моделям (Ridge, небольшая нейросеть) по сравнению с бустингом.

Отправная точка — алгоритм 1 из статьи А. Сысоева (SUMMA 2023): отбор факторов по важности
бустинга с группировкой модификаций одного фактора.

## 2. Главные выводы (цикл 1)

1. **Деревьям форма безразлична** (известный факт, мы его проверили). 40 разных наборов
   модификаций: у бустинга R² меняется на 0.0015, у Ridge — на 0.27.
2. **Алгоритм из статьи, прочитанный буквально, ломается**: теряет лучший фактор на первом шаге,
   путает x1 и x10, рано останавливается. R² падает до 0.24 вместо 0.98.
3. **Исправленный алгоритм** находит все 4 нужных фактора, но форму угадывает лишь в ~25%:
   важность дерева не отличает log x от x (см. п. 1). Поэтому Ridge на нём проседает.
4. **«Форма зависимости»** (наш основной метод) находит и факторы, и форму в 100% случаев на
   синтетике, стабилен и самый быстрый. **«Групповая важность»** — второй, форма верна в ~77%.
5. **Выигрыш в точности скромный и в основном у нейросети** (+0.013…+0.017 R²). Для Ridge
   «4 правильных признака» так же хороши, как «все 50», но в 12 раз компактнее и понятнее.
   Для бустинга разницы практически нет.
6. **На маленьких реальных данных (diabetes, 442 строки) выигрыша нет**, отбор нестабилен.
   Главная проверка впереди — 10 больших реальных датасетов.

## 3. Методы простыми словами

| Метод | Идея | Плюсы | Минусы |
|---|---|---|---|
| Исходные (`base_raw`) | только raw всех факторов | просто | Ridge теряет нелинейность |
| Все модификации (`base_fe_all`) | все 5 модификаций всех факторов, без отбора | **опорный**: с ним всё сравниваем | много признаков, дубли, неинтерпретируемо |
| Сысоев, статья (`sysoev_paper`) | псевдокод статьи буквально | — | три ошибки прочтения, см. п. 2 |
| Сысоев, исправленный (`sysoev_fixed`) | те же шаги + 4 исправления: явные группы, лучший берётся с первого шага, важность при уже выбранных, остановка по приросту R² | верные факторы | форма случайна |
| Групповая важность (`group_importance`) | перемешиваем все модификации фактора разом и смотрим, насколько упал R² бустинга; из группы берём модификацию, сильнее всех коррелирующую с y | честная важность фактора целиком | форма по корреляции — не всегда верна |
| Форма зависимости (`shape_fit`) | обучаем бустинг без взаимодействий на исходных x, достаём кривую «как y зависит от x» и смотрим, на какую из 5 форм она похожа | факторы и форма верны, быстро | предполагает, что факторы действуют по отдельности; при слабой кривизне выбор хрупкий |
| Boruta (`boruta`) | сравнивает важность признака с важностью его перемешанной «тени» | статистический тест | не убирает дубли: оставляет 20–35 признаков |
| RFE (`rfe`) | выбрасываем 20% самых неважных, повторяем | стандартный способ | нестабилен, форма случайна |

Близкие известные идеи (упоминать со ссылками): ACE (Breiman, Friedman, 1985),
преобразование Бокса–Кокса (1964), обобщённые аддитивные модели GAM (Hastie, Tibshirani, 1990),
EBM (Lou, Caruana и др., 2012; InterpretML). «Форма зависимости» — их сочетание, а не новое открытие.

## 4. Как читать отчёт

**Таблица по датасету.** Для каждого метода: число признаков, R² трёх моделей, в скобках
**Δ** — насколько R² больше (+) или меньше (−), чем у «Все модификации», на тех же фолдах.

**Значки:**
- ▲ — метод **значимо лучше** опорного, и разница не меньше 0.005 R²;
- ▼ — **значимо хуже**, разница не меньше 0.005;
- ≈ — разница статистически есть, но меньше 0.005 — на практике её нет;
- пусто — разница не доказана (может быть шумом).

Откуда «значимо»: каждый метод прогоняется на 15 одинаковых разбиениях (5 фолдов × 3 сида).
**Тест Уилкоксона** проверяет, выигрывает ли метод систематически, а не случайно.
**Поправка Холма** нужна, потому что мы сравниваем сразу 7 методов: чем больше сравнений,
тем легче случайно «найти» выигрыш; Холм делает порог строже.

**Стабильность** — насколько похожи наборы признаков на разных фолдах (индекс Жаккара:
1 — всегда одно и то же, 0 — каждый раз разное). Нестабильный отбор нельзя интерпретировать.

**Восстановление истины** (только синтетика, где ответ известен):
точность — доля выбранных факторов, которые действительно нужны; полнота — доля нужных, которые
найдены; **верная форма** — доля, где у фактора выбрана ровно истинная модификация.

**Общий рейтинг.** В каждом «блоке» (датасет × модель) методы ранжируются по R²: 1 — лучший.
Средний ранг — итог. **Тест Фридмана** отвечает на вопрос «различаются ли методы вообще»
(p < 0.05 — да). **Критическая разница (CD) Неменьи** — насколько должны отличаться средние ранги,
чтобы два метода считались разными.

## 5. Что сказать Сысоеву

Тон — «мы воспроизвели и развили», а не «в статье ошибки».

1. Воспроизвели алгоритм 1. При **буквальном** прочтении псевдокода три места дают сбой:
   на шаге i = 0 лучший признак удаляется, но не попадает в результат; группа выделяется
   по началу имени (`x1` захватывает `x10`); порог t = 0.1 применяется к перенормированным
   весам и рано обрывает цикл. Вероятно, в вашей реализации было иначе — уточнить.
2. С четырьмя исправлениями алгоритм находит все нужные факторы. Но **форму выбирает
   случайно**, и это принципиальное ограничение, а не ошибка: важность в деревьях не различает
   монотонные модификации одного фактора.
3. Предложение: выбирать форму по **форме зависимости**, которую выучил бустинг
   (partial dependence / SHAP). На синтетике — 100% верных форм.
4. План: 10 реальных датасетов (в т.ч. производственные), CatBoost + SHAP, подбор
   гиперпараметров Optuna, и **АКИ как мера важности групп** — ваша тема, это может быть
   общим разделом совместной статьи на SUMMA.
5. Вопросы: есть ли исходный код реализации из статьи? На каких данных она проверялась?
   Интересно ли развить часть с АКИ?

## 6. Как запустить

Из папки `diploma_fs` (установка — в [README](../README.md)):

```bash
python scripts/check_env.py            # всё ли установлено
python scripts/run.py --method all     # все методы на встроенных датасетах (10–20 мин)
python scripts/theory_check.py         # проверка «деревьям форма безразлична»
python scripts/report.py               # отчёт docs/REPORT.md и графики
```

Свой датасет: `python scripts/run.py --method all --csv data/файл.csv --target столбец`
(+ `--time-col дата` для временных рядов, `--sample 10000` для больших файлов).

После прогона закоммитьте `docs/REPORT.md`, `results/*.csv`, `results/theory_check.json`
и `results/figures/*.svg` (папка `results/raw/` в git не идёт).

## 7. Словарик

| Термин | Простыми словами |
|---|---|
| Фактор | исходный столбец данных (x1, «площадь») |
| Модификация | преобразование фактора: raw, log, sqrt, sq, inv |
| Группа | все модификации одного фактора |
| Отбор признаков | выбор, какие признаки дать модели |
| R² | доля объяснённого разброса y: 1 — идеально, 0 — как угадывать среднее |
| MAE / RMSE | средняя ошибка в единицах y (RMSE сильнее штрафует крупные промахи) |
| Фолд | одна из 5 частей данных; модель учится на 4, проверяется на 5-й |
| Утечка | когда при обучении случайно «подсмотрели» тестовые данные; результат завышен |
| Ridge | линейная регрессия со штрафом за большие коэффициенты |
| MLP | небольшая нейросеть (слои 32 и 16 нейронов) |
| Бустинг (HGB) | ансамбль деревьев, каждое исправляет ошибки предыдущих |
| Partial dependence (PD) | кривая «как прогноз меняется при изменении одного фактора» |
| SHAP | вклад каждого фактора в конкретный прогноз |
| АКИ | анализ конечных изменений (метод Сысоева): вклад фактора при конечном, а не бесконечно малом изменении |
| p-value | вероятность увидеть такую разницу случайно; < 0.05 — считаем неслучайной |
| Поправка Холма | делает порог строже, когда сравнений много |
| Жаккар | похожесть двух наборов: общих элементов / всех элементов |
| Средний ранг | среднее место метода по всем блокам; меньше — лучше |
| CD | критическая разница рангов: меньше неё — методы не различимы |
