# Гипотеза «Число попыток» (ветка research/hpo-trials)

Записана 03.10.2026, **до** прогона с настоящими CatBoost / XGBoost / LightGBM и Optuna.

## Утверждение

При базовой настройке Optuna (случайная проверочная выборка) увеличение числа попыток улучшает оценку на проверке,
но не улучшает модель на будущих данных: чем больше попыток, тем сильнее настройка подгоняется под проверочную выборку.

## Что меняем

Только число попыток: 10, 25, 50, 100. Считается одно исследование на 100 попыток; результат для бюджета k —
лучшая по проверке попытка из первых k (при том же seed это то же самое, что запуск на k попыток).

## Критерий

Гипотеза **подтверждается**, если при переходе от 25 к 100 попыткам (медиана по всем датасетам, моделям и отрезкам):

1. ошибка на проверке падает не менее чем на 2%;
2. ошибка на будущем падает меньше чем на 1% (или растёт);
3. разрыв «будущее против проверки» при 100 попытках больше, чем при 10.

Гипотеза **отвергается**, если ошибка на будущем падает на 1% и больше — тогда дополнительные попытки окупаются.

## Что это даёт диплому

Практическое правило «сколько попыток достаточно» для слабого компьютера и цифра, сколько времени счёта тратится впустую.

## Запуск

```bash
python scripts/run_hpo.py --experiment h_trials
python scripts/report_hpo.py --experiment h_trials
```
