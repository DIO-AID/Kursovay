# Дипломная работа — описание для руководителя

## Тема (предварительная)
**«Исследование поведения байесовской оптимизации гиперпараметров (TPE) методами визуализации плотностей распределения»**

---

## 1. Цель работы
Исследовать алгоритм байесовской оптимизации TPE (Tree-structured Parzen Estimator) на примере настройки гиперпараметров градиентного бустинга (XGBoost, LightGBM, CatBoost). Основной фокус — визуализация и интерпретация процесса поиска, а не просто подбор параметров.

## 2. Задачи
1. Разработать модульный ML-пайплайн для проведения экспериментов (загрузка данных, предобработка, обучение, оценка, визуализация)
2. Реализовать честное сравнение Grid Search и Optuna (TPE) на идентичных пространствах гиперпараметров
3. Разработать систему кастомной визуализации поведения TPE: density ratio l(x)/g(x), эволюция распределений параметров, exploration vs exploitation
4. Исследовать влияние модифицированного SHAP-отбора признаков (алгоритм Сысоева) на стабильность TPE
5. Сравнить 3 модели градиентного бустинга по чувствительности к выбору гиперпараметров
6. Сформулировать выводы о поведении TPE и рекомендации по настройке

## 3. Архитектура проекта

```
app/                  — Streamlit UI + пайплайн (6 вкладок аналитики)
src/                  — Core ML модули (11 моделей, стекинг, FE, SHAP)
tuning/               — Optuna (search_spaces, TPE tuner)
Final/results_fine/   — Результаты честного сравнения Grid vs Optuna
data/                 — California Housing
configs/              — Конфиги моделей
experiments/          — Batch эксперименты
```

## 4. Условия экспериментов

**Данные:**
- California Housing (20 640 записей, 9 признаков)
- Целевая переменная: median_house_value
- Split: train/test = 80/20, random_state=42
- Пропуски: total_bedrooms (207) — медианная импутация
- Категориальные: ocean_proximity — OneHot encoding
- Масштабирование: StandardScaler (только для LinearRegression)

**Модели:**
- XGBoost: 9 гиперпараметров
- LightGBM: 9 гиперпараметров
- CatBoost: 6 гиперпараметров
- LinearRegression: без тюнинга (baseline)

**Optuna:**
- Сэмплер: TPESampler (multivariate, seed=42)
- Pruner: MedianPruner
- Количество trials: 1000 на модель
- Метрика: R² (val)

**Grid Search (для честного сравнения):**
- Те же пространства, что и Optuna, но дискретные (сетка)
- Идентичные значения через suggest_categorical в Optuna
- Checkpoints каждые 50 комбинаций

## 5. Ключевые результаты

### Baseline (дефолтные параметры)

| Модель | R² | RMSE | MAE |
|--------|------|--------|--------|
| LinearRegression | 0.6254 | 70060 | 50670 |
| XGBoost | 0.8292 | 47309 | 31645 |
| LightGBM | 0.8262 | 47727 | 32067 |
| CatBoost | 0.8396 | 45844 | 30555 |

### Честное сравнение Grid vs Optuna (1000 trials)

| Модель | Grid R² | Grid время | Optuna R² | Optuna время |
|--------|---------|-----------|-----------|-------------|
| XGBoost | **0.8452** | 15.8 мин | **0.8452** | 1.7 мин (9.3× быстрее) |
| LightGBM | 0.8411 | 4.3 мин | 0.8392 | 0.4 мин (10.8× быстрее) |
| CatBoost | 0.8358 | 46.5 мин | 0.8358 | 6.7 мин (6.9× быстрее) |

**Главный вывод:** При идентичных пространствах параметров Optuna не превосходит Grid Search по качеству, но в 7–11 раз быстрее.

### SHAP-отбор признаков (алгоритм Сысоева)

| Конфигурация | R² | Отклонение |
|-------------|-----|-----------|
| Baseline (8 признаков) | 0.829 | — |
| FE (173 признака) | 0.827 | −0.2% |
| FE + SHAP (8 отобранных) | 0.836 | **+0.9%** |
| FE params → SHAP | 0.839 | **+1.2%** |

**Вывод:** SHAP-отбор восстанавливает R² после Feature Engineering, устраняя мультиколлинеарность.

## 6. Компромиссы в проекте (из практики)

Каждое улучшение в ML-пайплайне имеет цену:

| Улучшение | Выигрыш | Плата |
|-----------|---------|-------|
| **Кросс-валидация** | Честная оценка, защита от переобучения под split | Время × K-fold (обычно ×5) |
| **Pruning (ранняя остановка)** | Экономия 50–70% времени | Риск отсечь потенциально хороший trial |
| **Feature Engineering** (173 признака) | Больше информации для модели | Мультиколлинеарность, шум, падение R² |
| **Grid Search** | Гарантированный полный перебор | Экспоненциальный рост комбинаций (CatBoost: 46 мин на 864) |
| **Optuna (TPE)** | Быстрый поиск (×10) | Нет гарантии нахождения глобального оптимума |
| **Streamlit UI** | Интерактивная визуализация | Перезапуск при обновлении страницы, потеря состояния |
| **SHAP-отбор** | Устранение мультиколлинеарности | Вычислительная стоимость SHAP, потеря информации |

**Основной компромисс в работе:** между качеством/полнотой и скоростью/сложностью. TPE (Optuna) выбирает скорость, Grid Search — полноту. FE даёт больше признаков, но создаёт корреляции. SHAP решает корреляции, но теряет часть информации.

## 7. Поведение TPE (наблюдения)

1. **Сходимость:** TPE сужает область поиска вокруг лучших значений после ~200-300 trials
2. **Parameter importance:** learning_rate и n_estimators — наиболее влиятельные параметры для всех 3 моделей
3. **Риск переобучения:** при >500 trials TPE начинает фокусироваться слишком узко — нужен pruner
4. **CatBoost:** iterations делает Grid Search непрактичным (46 мин vs 6.7 мин у Optuna)
