## Стандартный цикл коммита (выполняй всегда)
```bash
git status                 # посмотреть что изменилось
git diff                   # проверить изменения перед коммитом
git add <файлы>            # добавляй точечно, НЕ git add -A вслепую
git commit -m "сообщение"
git push origin main       # если нужно залить
```

## Формат сообщения коммита
Используй мини-префиксы по типу изменения:
- `feat:` — новая функциональность (новая модель, новый пайплайн)
- `fix:` — исправление бага
- `refactor:` — рефакторинг без изменения поведения
- `docs:` — документация
- `exp:` — результаты эксперимента (новый конфиг, таблица результатов)
- `tune:` — изменения параметров Optuna/тюнинга

Примеры:
```
feat: добавлен SHAP-анализ признаков
fix: падение при пустом test.csv
exp: Optuna 1000 итераций XGBoost R2=0.8609
```

## Правила
1. Перед коммитом всегда проверяй `git status` и `git diff`
2. Не добавляй в коммит большие данные/артефакты — только код и конфиги
3. Один коммит = одна логическая задача
4. Если сомневаешься в изменении — покажи пользователю `git diff` перед commit
5. Не делай `git add .` без проверки, что реально попадёт в индекс
